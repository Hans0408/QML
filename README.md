# Tensor Network Pretraining in Quantum Machine Learning

This repository contains the numerical implementation for my MSc research project on **classical pretraining of variational quantum circuits (VQCs) using matrix product states (MPS)**.

The central idea is to parameterise the MPS and VQC using the **same underlying parent transformations**. This creates a direct correspondence between their trainable parameters, allowing an MPS to be trained classically and its learned parameters to be transferred directly to the VQC **without an intermediate decomposition or parameter-matching procedure**.

The method is demonstrated on a binary **Bars-and-Stripes** classification task using two parameterisations:

1. **Dense SO(n) parameterisation** using Givens rotations.
2. **Efficient circuit parameterisation** using layers of `RY` and controlled-`RY` gates.

---

## Motivation

Variational quantum circuits are promising models for quantum machine learning, but their optimisation can be expensive. Circuit evaluations and gradient estimation can require many quantum executions, and optimisation may also suffer from problems such as poorly conditioned regions or barren plateaus.

The goal of this project is therefore not simply to improve final classification accuracy. Instead, it asks:

> **Can part of the VQC optimisation be performed classically using an MPS, so that the quantum circuit starts closer to a good solution?**

The approach used here is:

```text
Classical data
      │
      ▼
Train MPS classically
      │
      │ Direct parameter transfer
      ▼
Initialise VQC
      │
      ▼
Continue VQC optimisation
```

The important feature is that the MPS tensors and VQC gates are generated from the **same trainable parameters**, making the transfer direct.

## Repository Structure

```text
.
├── cleaned_script_1.py
├── cleaned_script_2.py
└── README.md
```

### `cleaned_script_1.py`

Implements the **dense SO(n) parameterisation**.

The parent matrices are special orthogonal matrices constructed from trainable Givens rotations. The MPS uses selected parts of these matrices as tensors, while the VQC uses the complete matrices as quantum gates.

This allows the trained MPS angles to be transferred directly to the corresponding VQC.

### `cleaned_script_2.py`

Implements the **efficient circuit-based parameterisation**.

Instead of constructing a general dense transformation, each parent matrix is generated by a structured circuit containing:

- trainable single-qubit `RY` rotations;
- nearest-neighbour controlled-`RY` rotations;
- alternating entangling directions between successive layers.

The same structured transformation is used to construct both the MPS tensors and VQC gates.

This preserves direct MPS-to-VQC parameter transfer while giving the transformations an explicit elementary-gate structure.

## Method

### 1. Classical feature map

For each image pixel \(x \in [0,1]\), the MPS uses the local feature map

\[
\phi(x) =
\begin{bmatrix}
\cos(\pi x/2) \\
\sin(\pi x/2)
\end{bmatrix}.
\]

The full image representation is formed from the product of these local feature vectors.

---

### 2. MPS training

An MPS classifier is trained classically with PyTorch.

The final MPS tensor contains a binary class index together with an auxiliary environment index. Class probabilities are calculated by:

1. contracting the MPS with the encoded input;
2. squaring the resulting amplitudes;
3. summing over the environment index;
4. normalising the two class weights.

---

### 3. Direct MPS-to-VQC transfer

The key construction is that the MPS tensors and quantum gates depend on the **same parameters**.

For the dense implementation,

\[
U(\theta) \in SO(n),
\]

where the matrix is constructed from Givens rotations.

The MPS tensors are extracted from parts of \(U(\theta)\), whereas the corresponding VQC applies the complete transformation.

After classical MPS training:

```python
first_thetas = mps_model.first_thetas
middle_thetas = mps_model.middle_thetas
last_thetas = mps_model.last_thetas
```

are transferred directly into the VQC.

No checkpoint conversion, SVD-based compilation, or parameter-fitting procedure is required.

---

### 4. Efficient parameterisation

The second implementation replaces a generic dense parent matrix with a shallow structured circuit.

For a block acting on \(q\) qubits, one circuit layer contains:

- \(q\) trainable `RY` gates;
- \(q-1\) trainable nearest-neighbour controlled-`RY` gates.

Therefore, for \(L_c\) circuit layers, the number of gates in a block scales as

\[
N_{\mathrm{gates}} = L_c(2q-1).
\]

For fixed \(L_c\), this grows linearly with the number of qubits.

## Dataset

The experiments use the **Bars-and-Stripes** dataset.

For the default `2 x 2` case:

### Class 0 — vertical bars

```text
0 1
0 1
```

or

```text
1 0
1 0
```

### Class 1 — horizontal stripes

```text
0 0
1 1
```

or

```text
1 1
0 0
```

Uniform all-zero and all-one patterns are excluded because they satisfy both the bars and stripes definitions.

The scripts generate the dataset synthetically and can optionally apply random bit-flip noise.

Default dataset settings:

```python
N_TRAIN_SAMPLES = 800
N_TEST_SAMPLES = 200
BAS_NOISE_PROBABILITY = 0.05
```

## Experiments

For each random seed, the pipeline performs the following comparison.

### Pretrained VQC

```text
Random MPS initialisation
        │
        ▼
Classical MPS training
        │
        ▼
Transfer trained parameters
        │
        ▼
Pretrained VQC
        │
        ▼
VQC optimisation
```

### Non-pretrained VQC

```text
Random VQC initialisation
        │
        ▼
VQC optimisation
```

The two branches use the same VQC architecture. The main comparison is therefore whether classical MPS pretraining gives the VQC a better starting point.

---

## Dense SO(n) Experiments

The dense parameterisation was studied for different MPS bond dimensions.

The project found that the usefulness of pretraining depends strongly on the expressivity of the MPS:

- for small bond dimension, the hot-start advantage can be limited;
- for sufficiently expressive MPS models, the pretrained VQC starts substantially closer to a low-loss/high-accuracy region;
- a randomly initialised VQC can often eventually reach a similar solution, but requires more quantum optimisation to do so.

The purpose of the pretraining is therefore primarily to improve **initialisation and early optimisation**, rather than necessarily increasing the final achievable accuracy.

---

## Efficient Circuit Experiments

The efficient implementation fixes the bond dimension and varies the number of structured circuit layers \(L_c\).

The same expressivity trade-off appears:

- very shallow circuit blocks may not provide enough MPS expressivity;
- increasing \(L_c\) improves the quality of the transferred initialisation;
- sufficiently expressive structured blocks preserve the main pretraining effect seen with dense SO(n) matrices.

This is important because it shows that the hot-start behaviour does not require a completely general dense transformation.

---

## Additional Trainable VQC Gates

The scripts also support extending the pretrained VQC with additional trainable two-qubit gates:

```python
USE_NEAR_IDENTITY_EXTENSION = True
EXTRA_GATE_LAYERS = 1
EXTRA_GATE_SCALE = 1e-3
EXTRA_GATE_TOPOLOGY = "all_to_all"
```

These gates are initialised close to the identity so that the pretrained solution is approximately preserved at the beginning of VQC training.

The available topologies are:

```text
all_to_all
linear
nonlocal
```

The experiments in the project found that additional trainable layers can improve early VQC optimisation, although increasing the number of extra layers gives diminishing improvements for the task considered.

## Running the Code

### Dense SO(n) version

```bash
python cleaned_script_1.py
```

### Efficient circuit version

```bash
python cleaned_script_2.py
```

Each script will:

1. generate the Bars-and-Stripes dataset;
2. train the MPS;
3. initialise a pretrained VQC using the MPS parameters;
4. initialise an equivalent non-pretrained VQC;
5. train both VQCs;
6. perform the final finite-shot evaluation;
7. print a comparison summary.

`BOND_DIM` must be a power of two:

```text
2, 4, 8, 16, ...
```

because the bond space is mapped to a corresponding number of qubits.

## Quantum Simulation

The VQCs are implemented with **PennyLane** using:

```python
qml.device("default.qubit", ...)
```

During training:

```python
TRAINING_SHOTS = None
```

so the simulator evaluates probabilities exactly.

For the final evaluation:

```python
EVALUATION_SHOTS = 1000
```

to provide a finite-shot, hardware-like estimate of the classifier performance.

## Main Findings

The numerical experiments support three main observations:

1. **Direct parameter transfer is possible.**  
   By constructing the MPS tensors and VQC gates from the same parameters, classical MPS optimisation can be transferred directly into the quantum model.

2. **Pretraining quality depends on expressivity.**  
   If the MPS or structured circuit is too restricted, the transferred parameters provide little advantage. With sufficient capacity, the VQC receives a clear hot start.

3. **The effect survives a structured gate parameterisation.**  
   The efficient `RY`/controlled-`RY` construction retains the main pretraining behaviour while avoiding the need to first construct and later decompose generic dense multi-qubit transformations.

---

## Limitations

This repository contains a proof-of-concept implementation.

The main experiments use a small `2 x 2` Bars-and-Stripes classification problem and simulated quantum circuits.

The current results therefore do not establish a practical quantum advantage.

Important future directions include:

- larger image sizes and classification tasks;
- additional datasets;
- finite-shot VQC training;
- realistic hardware noise;
- execution on real quantum devices;
- studying scaling with bond dimension and circuit depth;
- comparing the quantum optimisation cost before and after pretraining.
